# TRS-398 Rev.1: определение абсолютной дозы

*English version: [README.en.md](README.en.md)*

Программа для расчёта поглощённой дозы в воде по TRS-398 Rev.1 (фотоны и электроны высоких энергий): база данных в одном файле,
роли, утверждение вторым лицом, тренды выхода (контрольные карты, CUSUM) и печать протокола в PDF по форме рабочего листа «Расчёт».
Работает на обычном ноутбуке с Windows, **без Docker и без установки баз данных**. Интерфейс на **русском и английском** (переключатель RU / EN вверху).

> Образовательное и исследовательское использование. Программа не является сертифицированным медицинским
> изделием: каждый результат нужно проверять независимо. См. [NOTICE.md](NOTICE.md).

## Установка (Windows 10/11)

1. Скачайте со страницы **Releases** файл `TRS398-setup-….exe`, запустите его (права администратора не нужны). Без установки: `TRS398-portable-….zip`, распакуйте в любую папку.
2. Запустите **TRS-398**. В трее (возле часов) появится значок, а в браузере откроется `http://localhost:8000`.
3. При первом запуске программа спросит логин и пароль администратора (придумайте свои). Дальше: «Пользователи» (физики и проверяющие), «Оборудование» (аппарат, пучки, камера и калибровка), «Измерения».

Windows может показать предупреждение «SmartScreen» (у программы нет платной цифровой подписи): «Подробнее → Выполнить в любом случае».
Подробно: [docs/INSTALL.md](docs/INSTALL.md), English: [docs/INSTALL.en.md](docs/INSTALL.en.md).

Меню значка в трее: открыть программу; сделать резервную копию; папка с данными; восстановить из копии; журнал ошибок; запускать вместе с Windows;
разрешить подключение с других компьютеров; выход. Закрытие окна браузера программу не останавливает, останавливает пункт «Выход».

**Несколько физиков.** Программа работает на ноутбуке одного из них; остальные открывают в браузере `http://имя-ноутбука:8000`
(включите пункт «Разрешить подключение с других компьютеров», [docs/NETWORK.md](docs/NETWORK.md)). Данные и пользователи общие, хранятся на этом ноутбуке.
Руководство для физиков: [docs/USER_GUIDE.md](docs/USER_GUIDE.md) (есть и в самой программе, пункт «Справка»).

**Где данные.** Установленная версия: `%LOCALAPPDATA%\TRS398\data` (кнопка «Папка с данными» в меню значка).
Портативная версия: папка `data` рядом с программой. Вся база — один файл `trs398.db`; резервные копии — в `backups` рядом.

### Резервные копии и восстановление

Программа делает копию при запуске и затем каждый день после 02:00 (время компьютера), если она запущена; хранит 30 дней
(`BACKUP_HOUR`, `BACKUP_KEEP_DAYS` в переменных окружения). Файлы `backups	rs398_ГГГГ-ММ-ДД_ЧЧММСС.db.gz`
содержат данные пользователей и хэши паролей, держите папку закрытой. Копия в любой момент: пункт меню значка
или кнопка «Сделать копию сейчас» на странице **«Копии»**. **Важно:** по умолчанию копии лежат на том же ноутбуке. Укажите **вторую папку** на странице «Копии» (другой диск, флешка, сетевая папка или папка облака): каждая новая копия будет записываться и туда, а при сбое вы увидите предупреждение на странице «Копии» и в «О программе».

**Восстановить:** пункт меню значка «Восстановить из копии…» (или ярлык в меню «Пуск»), выбрать номер копии, ввести `YES`.
Программа закроется, **текущая база сначала сохранится в `backups\keep`**, затем будет заменена копией. Запустите программу снова.

**Перенести на другой ноутбук:** установите программу, положите файл копии в `backups`, восстановите его. Пароли переносятся вместе с копией.

**Новая пустая база:** закройте программу («Выход»), переименуйте или удалите `trs398.db` в папке данных (сначала сделайте копию), запустите программу: она предложит создать администратора.

Проверка копии: ярлык «Проверить копию» в меню «Пуск». Проверка, что все сохранённые результаты воспроизводятся из исходных данных: `python tools/recompute_check.py` (из исходников).

### Переход с версии 1.x (Docker, PostgreSQL)

Данные переносятся один раз скриптом `tools/pg_to_sqlite.py` (нужны Python и работающий контейнер версии 1.x, база только читается; он же сверяет каждое значение и трендовое представление).
Версия 1.x остаётся доступной в ветке `v1.x` репозитория.

## Что умеет

- Фотоны и электроны: kTP, kpol, ks (метод двух напряжений), kvol (FFF), kQ (Таблицы 16, 20, 21), Dw(zref), Dw(zmax).
- Рабочий процесс: черновик → на проверке → утверждено (или возвращено). Автор не может утвердить свою запись.
  Утверждённую запись нельзя изменить, только заменить с указанием причины.
- **Протокол**: страница печати и PDF (кнопки «Печать» и «Скачать PDF») в виде листа «Расчёт» (жёлтые, голубые и зелёные ячейки, формулы, галочки) плюс приложение «Оценка неопределённости» (этапы 1–2, тип A по журналу, uc и U, примечания, решение о перекалибровке) по листу «Неопределённость».
- **Сравнение энергий** (меню «Сравнение энергий»): все энергии одного аппарата вместе: состояние каждой, наложенные ряды, карта «энергия × месяц», поиск общего сдвига нескольких энергий в один месяц и корреляции между энергиями.
- Таблицы сортируются по клику на заголовок, верхняя панель и шапки таблиц закреплены.
- Параметры разделов 1–3 листа (аппарат, пучок, камера, калибровка, полярности, электрометр) задаются в «Оборудовании»; на листе расчёта они только показываются. Показания (iii) и (iv) подставляются из первой записи пучка и их можно менять.
- Тренды: контрольные границы ±2σ/±3σ, правила сигналов, CUSUM, прогноз выхода за ±2 %, фиксируемый базовый период.
- Администратор: пользователи, оборудование, журнал аудита, копии, очистка базы.
- Два языка (русский, английский) интерфейса, протокола/PDF, справки и скриптов запуска.

## Роли

| Роль | Права |
|---|---|
| наблюдатель | просмотр измерений и трендов |
| физик | ввод измерений, отправка на проверку, калибровки камер |
| проверяющий | утверждение и возврат чужих записей, замена утверждённых |
| администратор | всё выше, пользователи, аппараты и пучки, базовый период SPC, журнал аудита, очистка базы |

## Очистка базы

Администратор: меню «Очистка базы». Нужны выбор области, причина, пароль и слово `УДАЛИТЬ` (в английском интерфейсе `DELETE`). Удаляются
измерения/результаты и/или исторические журналы. Пользователи, оборудование, справочники и журнал аудита
сохраняются, сама очистка записывается в аудит. Обычные запросы программы не могут удалять историю (защищают триггеры базы),
это возможно только через служебные операции `app/dbops.py` для активного администратора. Перед очисткой сделайте резервную копию.

## Демонстрационные данные

`python tools/seed_demo.py` заполняет базу на 3 года (ежемесячно; `--years N` или `--months N` меняют срок, `--independent` убирает связи между энергиями; в одном аппарате энергии связаны общей частью (сезонный ход монитора, дрейф) и групповыми событиями: все фотоны после сервиса мишени, все электроны после замены фольги, электроны от 9 МэВ вместе, 6 MV с фильтром и без него): **2 аппарата** (TrueBeam, Versa HD) и **15 пучков**: фотоны 6, 6 FFF, 10 FFF, 15 MV и электроны 6, 9, 12, 15 MeV (360 утверждённых записей).
Камеры и калибровки (условные значения): у TrueBeam по шаблонам 2.0 (SNC600c Farmer, ND,w = 0,05138 Гр/нКл; PTW 34001 Roos, ND,w = 0,5791 Гр/нКл),
у Versa HD свои (PTW 30013 Farmer и IBA NACP-02, электрометр IBA Dose1), плюс две резервные камеры с действующей калибровкой (IBA FC65-G Farmer, второй PTW 34001 Roos).
У каждой рабочей камеры две калибровки: прошлая (истекла, в форме недоступна) и действующая. Записи помечены DEMO, выполнены «Демо-физиком» и утверждены «Демо-проверяющим»
(отключённые учётные записи, войти под ними нельзя). В данных есть что показать: выход за допуск и перенастройка (Versa HD 6 MV), медленный дрейф (TrueBeam 12 MeV),
общий сдвиг нескольких энергий в один месяц (TrueBeam). Пучки с вашими реальными данными пропускаются. Удалить только добавленное: `python tools/seed_demo.py --remove`.
Перед запуском сделайте резервную копию. Скрипт работает с базой из папки данных (`TRS_DATA`), программу на это время закройте.

## Разработка

```
python -m venv .venv && .venv\Scripts\pip install -r requirements-dev.txt
.venv\Scripts\python -m pytest -q tests
python run.py            # сервер без значка в трее, http://localhost:8000
python tools/build_windows.py [--installer]   # сборка: нужны pystray, pillow, pyinstaller, для установщика Inno Setup 6
```

Тесты используют временную базу SQLite. PDF печатает установленный Edge или Chrome в «безголовом» режиме (`app/pdf.py`, при их отсутствии тест пропускается).
Релиз: тег `v2…` запускает сборку установщика и zip в GitHub Actions.

### Языки

Русский — исходный язык интерфейса, английский берётся из справочника фраз `app/i18n/en.json` (`app/i18n.py` переводит готовую страницу).
После изменения любого русского текста интерфейса: `python tools/i18n_extract.py` показывает фразы без английского текста, `--todo файл.json` выгружает их для перевода,
`--merge файл.json` загружает переводы. Тест `tests/test_i18n.py` падает, если у фразы нет английского текста или на странице в английском режиме остался русский.
Язык по умолчанию задаёт переменная `TRS_LANG` (`ru` или `en`).

## Структура

- `core/`: расчёт (фотоны, электроны, SPC), справочные таблицы в `core/data/`
- `app/`: веб-приложение (FastAPI, Jinja2, HTMX), `app/db.py` и `app/migrations/` (SQLite), `app/protocol.py` собирает данные протокола
- `tray.py`, `run.py`, `trs398.spec`, `installer/`: запуск, значок в трее, сборка
- `importers/`: перенос таблиц и журналов из xlsm (только чтение)
- `docs/DESIGN.md`: разбор исходных таблиц, формулы, модель данных (English: `docs/DESIGN.en.md`)
